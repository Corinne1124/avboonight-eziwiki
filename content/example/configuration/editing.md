# 在线编辑

发现错字的人离修好它只差一步时，wiki 才会长大。开启编辑器后，读者在页面上就能改内容：改动以提交（commit）的形式写回仓库，由已有的 Pages 工作流自动重新构建并上线——不需要服务器，也不需要任何人本地跑一次 `npm run build`。

这个站点是纯静态导出的，浏览器里没有任何可以写文件的地方，所以"在线编辑"的落地方式是：**把改动提交到 GitHub 仓库**。

## 开启

在 `payload/config.ts` 中：

```typescript
export const payload: Payload = {
  global: {
    repoUrl: 'https://github.com/you/your-wiki', // 编辑器只认识 GitHub 仓库
  },
  editor: {
    enabled: true,
    // branch: 'main',  // 可选；默认取 global.editBranch，再默认为 main
  },
};
```

开启后会出现两个入口：

- 每个页面底部的「**在此编辑**」——编辑当前页面；
- 侧边栏顶部的「**新建页面**」按钮——写一个还不存在的页面（在首页也能用）。

## 密码是什么

密码就是一把**对本仓库有写权限的 GitHub Token**。它由读者自己输入，只保存在他自己的浏览器里（勾选"在此设备上记住"时才写入 `localStorage`），并且只发送给 `api.github.com`。

推荐用 fine-grained token，权限给到最小：

1. GitHub → Settings → Developer settings → **Personal access tokens → Fine-grained tokens** → Generate new token；
2. **Repository access** 选择 Only select repositories，勾选本站对应的仓库；
3. **Permissions → Repository permissions → Contents** 设为 **Read and write**（其余保持 No access 即可）；
4. 生成后复制，粘贴到编辑器里。Token 只在生成时显示一次。

输入后编辑器会先调用 `GET /user` 与 `GET /repos/{owner}/{repo}` 验证：口令不对会说"密码被拒绝"，账号没有写权限会直接说"无权写入"，而不是等到保存时才失败。

> [!WARNING] 静态站点的安全边界
> 纯静态站点没有服务端，因此**无法**做到"只有知道密码的人才能看到编辑界面"这种保护：仓库地址是公开的，编辑器代码也是公开的。真正的权限来自 GitHub Token 本身——没有 token 的人即使打开编辑器也提交不了任何东西。
>
> 也就是说：这个功能不会给任何人新增权限（能提交到仓库的人本来就能改所有页面），它只是把"发现错误"到"修好它"之间的距离缩短了。如果你的仓库是私有的、或者不希望任何人在浏览器里输入 token，把 `editor.enabled` 设为 `false` 即可，入口会完全消失。

## 能做什么

| 操作             | 说明                                                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 编辑正文         | 修改 Markdown 正文并保存                                                                                                            |
| 编辑 frontmatter | 字段模式可改 `title`、`description`、`order`、`tags`、`hidden`、`aliases`、`updated`                                                |
| 编辑源码         | 源码模式可编辑整个文件，包括字段模式无法表达的 frontmatter                                                                          |
| 新建页面         | 指定路径新建；路径以 `/` 结尾（`ailan/`）或写成 `ailan/index` 时，创建的是可挂载子页面的[目录页](/example/configuration/navigation) |
| 移动/重命名      | 在新路径写入同一内容，并把旧路径自动加进 `aliases`，然后删除旧文件——旧链接继续有效                                                  |
| 删除页面         | 二次确认后提交删除                                                                                                                  |

字段模式只会重写它认识的那几行：注释、未知字段、无法解析的嵌套结构都原样保留。如果整个 frontmatter 块复杂到无法安全重写，编辑器会自动切到源码模式，而不是把文件改坏。

## 保存之后

保存即提交，提交信息默认是 `docs: edit <路径>`（新建、移动、删除各有对应措辞），可以自己改。

仓库接到 push 后，`.github/workflows/deploy.yml` 会重新构建并部署 GitHub Pages——通常一两分钟后，改好的页面就出现在线上。**编辑器里的页面是上一次构建的结果**，所以保存后不会立即在浏览器里看到新内容，这是静态站点的固有节奏，不是失败。

## 隐私与开销

- 编辑器代码是**按需加载**的：只有真正点开编辑器的读者才会下载它，浏览页面的普通读者一个字节都不用付。
- Token 不会随站点构建产物发布，也不会写进任何 HTML；它只存在于输入它的那个浏览器里。
- 「退出」会立即清掉保存的 token。

## 常见问题

| 现象               | 原因                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| 密码被拒绝         | Token 拼错、已过期，或缺少 `Contents: Read and write`                 |
| 无权写入           | 该 token 对应的账号对仓库没有 push 权限（例如只给了 read）            |
| 页面载入失败       | 该页面的 `.md` 文件不在仓库里，或 token 没有读取该仓库的权限          |
| 提交被拒绝（409）  | 文件在编辑期间被别人改过：刷新页面重新打开编辑器即可                  |
| 保存成功但网站没变 | 部署还在跑；也可能是这次提交没有触发工作流（检查仓库的 Actions 页面） |
